I was responsible for defining, wiring and validating these exchanges for the stations of the deployed lines.

Description

L'usine de Vigo (Espagne, réservoirs à carburant en juste-à-temps séquencé) subissait des pertes de connexion intermittentes sur ses tags de données machine : 41 tags critiques sur les 2 227 tags OPC UA du site décrochaient sans schéma apparent, avec seulement deux jours de logs et des diagnostics manuels de plusieurs heures. J'ai conçu, comparé et mis en place une chaîne de supervision légère et sans licence — Node-RED → InfluxDB → Grafana — qui historise l'état de chaque tag (Good / Bad) sur plusieurs mois et alerte la maintenance dès qu'un tag décroche. Pour chaque poste de travail (WS), le tableau de bord montre l'état des 12 tags qui doivent dialoguer avec le serveur OPC UA — et donc, en aval, avec le PES. La même chaîne m'a ensuite servi à construire des tableaux de suivi machine pour l'atelier : état temps réel, vitesses des extrudeuses, et un monitoring automatique des changements de moule qui relie la démarche SMED aux données réelles des capteurs.

The Vigo plant (Spain, fuel tanks delivered just-in-sequence) suffered intermittent connection losses on its machine-data tags: 41 critical tags out of the site's 2,227 OPC UA tags dropped with no obvious pattern, with only two days of logs and hours of manual diagnosis. I designed, benchmarked and deployed a lightweight, licence-free monitoring chain — Node-RED → InfluxDB → Grafana — that records each tag's state (Good / Bad) over months and alerts maintenance as soon as a tag drops. For each workstation (WS), the dashboard shows the state of the 12 tags that must talk to the OPC UA server — and therefore, downstream, to the PES. I then reused the chain to build shop-floor machine dashboards: real-time status, extruder speeds, and automatic monitoring of mould changeovers that ties the SMED approach to actual sensor data.

  • Comparer deux architectures — pile Node-RED / InfluxDB / Grafana contre supervision par ping type Centreon — avec une matrice de décision pondérée sur huit critères (couverture fonctionnelle, fiabilité, scalabilité, effort, TCO, cybersécurité…)
